## Offline explicit reconciliation

The local operator script is disabled unless the exact enable argument and a strictly validated evidence file are supplied. It never sources `.env`, decrypts provider credentials, or performs live lookups. It requires an explicitly named local `DATABASE_URL`, an operator authorization reference scoped to this tenant/snapshot, the exact attempt/token/body hash, reason and evidence reference.

`node --import tsx scripts/reconcile-pulse-report-delivery.ts --enable-offline-reconciliation /absolute/path/evidence.json`

Decisions are immutable audited events: a real matching receipt (`confirmed_delivered`), definitive nonpublication evidence with a terminated/fenced old owner (`confirmed_not_sent`), or `remain_unknown`. A missing message in a bounded search, an expired lease or absent receipt is insufficient proof of nonpublication. Stale/concurrent decisions fail CAS. Positive resolution allows the next ordinal to revalidate; definitive no-send allows the same ordinal/bytes/route to retry. No bulk reset, force resend, replacement or retarget operation exists. A supplied human evidence reference is an audited decision, not cryptographic proof of Slack delivery. Purged binding information may leave a conservative manual hold.

Operational logs should include structured status, due/start/completion/delivery times and scoped IDs only, never report prose, source text, individual values, credentials, full errors or environment values.

Before snapshot persistence, a new qualifying strictly prior final may change history selection. Recovery retains the same obligation, current candidates, frontier, configuration and evidence. A fresh transaction locks the complete new history/current subject union, fences the old assembly owner, stores the reselected historical provenance and rebuilds all prose/dynamics/package. Current positive inputs never revise the initiated observation. After persistence, changed history stops the existing immutable snapshot; there is no rebase or replacement.
