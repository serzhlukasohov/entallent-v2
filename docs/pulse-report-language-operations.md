# Pulse report language operations

RPT-LANG separates company language from personal conversation language. `tenants.locale` and the existing report configuration revision are the company authority. Browser language and employee preference cannot change that authority. Accepted locales follow canonical ICU-supported BCP47; formatting support alone is not evidence of translation quality.

## Preparation and readiness

Preparation is an explicit application operation. There is no automatic startup task, scheduled population, backfill, GET-triggered translation or configuration-lock model call. `PreparePulseLanguageUseCase.execute({ locale, kind, source, tenantId? })` uses `PulseLanguageRepository` and the dedicated `PulseLanguageAdapter`. The caller supplies the exact versioned source inventory from `PULSE_ENGLISH_RESOURCES`; custom definition inventories use `title.<sha256(stableKey + NUL + exactTitle)>` and require a tenant ID. Custom definitions are generated and independently reviewed even in English. Private employee content must never enter generic catalogs.

Each preparation permits at most two candidates. Each candidate has at most one generation and one independent semantic review; SDK retries are disabled. TypeScript rejects missing or extra keys, changed interpolation slots, markup, oversized text, invalid locale and non-passing review before installation. Immutable accepted resources record exact source/text hashes and generation/review provenance. A changed source inventory requires its matching accepted resource; an older source hash cannot establish readiness.

Generic operational, disclosure, safe-signal, admin and engagement resources have built-in reviewed English sources. Other languages require accepted resources for each needed kind. Administrative reads return `companyLanguage.status=language_unavailable` until the exact admin catalog exists. Missing custom title resources remain explicitly unavailable. Personal switches require accepted operational and disclosure copy: an unsupported request remains content-free pending state and uses the last accepted language for the notice. Preparation does not change company configuration or activate a language in production.

## Historical safe display text

`PrepareAnalyticalRenditionUseCase.execute({ tenantId, analyticalId, locale })` loads only a currently permitted permanent deidentified analytical source. Its provider receives only that safe summary and support classification, not message IDs, private statements, source receipts or subject identity. Two bounded generation/review candidates are allowed. Installation revalidates source hash, authorization, retention, language and policy identity. Reads never generate missing text.

Renditions are separate display derivatives. They never replace canonical prose, become scoring/report inputs, change historical provenance or extend retention. Missing renditions have `translation_pending` status. Legacy canonical records retain null language provenance. Source withdrawal, partial lineage exclusion, permission changes, direct source deletion, subject/tenant erasure, dependency deletion and retention changes invalidate or purge derived text; publication cleanup also removes expired derivatives. No fallback to an older disallowed source is permitted.

## Canonical generation and personal selection

Before model execution, finalization durably captures the company locale and configuration revision for the exact working revision. It retains PostgreSQL timestamp precision for capture, score-cache and final-commit comparisons. Source/configuration fingerprint mismatch is a technical block. Language-only retries retain the original capture and cached score; a company-language edit does not rescore old meaning or overwrite historical canonical text. Prose provenance is separate from scoring provenance. Accepted locale safe-signal copy is the bounded generalized fallback; missing copy leaves retryable work rather than falsely finalized English.

Personal precedence is current explicit request, saved explicit choice, current substantive inference, saved inference, validated profile locale, then product English. Proposals arrive in the existing classification completion, with no additional detector call. Trusted DB receipt time plus inbound UUID orders durable changes. Numbers, agreement, quotes/code and uncertain mixed content do not establish inference. Unverified clocks may supply a current-turn hint but never advance durable history. Later resource readiness accepts a pending request at its original request clock. Committed outbound replay always keeps its original bytes.

Reviewed engagement/disclosure forms bind locale, version, source and exact shown text/full-body hashes. A later preference switch cannot change the previously delivered question or answer proof. Missing accepted engagement copy suppresses the probe; it cannot invent a rating. Legacy English receipts remain valid under their original contracts. Previously shown onboarding trust text and exact employee-confirmed statements remain verbatim when surrounding instructions change.

## Corrective source and recovery invariants

Native display-source authority is now a separate content-free record. It retains the original maximum native expiry and an irreversible dependency-loss marker while the analytical source exists. A currently retained watermark and receipt-backed revision must both exist; deleting either proof cannot turn a native source into legacy data or increase its lifetime. Source/user/tenant cascades remove authority along with the parent. Genuine legacy compatibility requires a positively identified immutable legacy cycle opening plus its exact approved definition/window/policy binding. Version-only, missing metadata and other unknown historical sources remain unavailable. Native mode also has its own positive immutable cycle-opening proof.

Authenticated setup with an unavailable company catalog displays an English recovery panel with the requested company locale explicitly named. Its actual document language is English until accepted resources exist. The same session, CSRF token and revision-checked company-language endpoint perform recovery. This state is distinct from authentication failure. Ready setup lifecycle/count copy uses full resource templates; storage enum values and employee/customer data remain unchanged.

Exact form composition keeps the approved engagement form at the end of the final body, placing any authorized disclosure before it. Existing ordinary/proactive disclosure gates still suppress undisclosed probes; combined-body regression is a defensive composition contract, not proof of a normal-load first-probe outage. Actual persisted and delivery-recorded body hashes remain authoritative. Personal resource reads reuse the resolver's transaction context and require no spare pooled connection.
