## Epic Review

Epic 2 established the safety substrate required before any real MAF runtime client, Python service, or user-facing MAF execution can exist. The completed slice made the runtime HTTP contract canonical, proved TypeScript and Python validation parity, introduced canonical proposed-action envelopes, persisted runtime attempt and action ledgers, enforced fallback eligibility from durable ledger state, and defined retry/error classification around the single BullMQ-owned runtime attempt number.

## Completed Scope

- Story 2.1: Chose neutral OpenAPI 3.1 at `packages/contracts/runtime/openapi.json` as the canonical runtime schema source and seeded shared TS/Python fixture validation.
- Story 2.2: Added framework-neutral runtime request, result, and error DTOs plus named OpenAPI-backed validators.
- Story 2.3: Replaced bare proposed actions with canonical action envelopes and lifecycle state.
- Story 2.4: Added persisted runtime attempt and action ledgers with idempotent, monotonic worker-side recording.
- Story 2.5: Added durable fallback barrier classification and the router fallback hook.
- Story 2.6: Added retry diagnostics, runtime error classification, cross-language retry-total validation, and stable failure reasons.

## Evidence

- `packages/contracts/runtime/openapi.json` is the canonical contract source, with shared fixtures consumed by TypeScript and Python validators.
- `packages/contracts/src/runtime-contract.ts` exports framework-neutral DTOs without MAF, FastAPI, Nest, or application-layer imports.
- Runtime diagnostics now carry `runtimeAttempt`, total retry count, and model/tool/HTTP retry counters.
- Runtime attempt and action ledgers are persisted in Postgres schema files and consumed by the worker repository.
- Fallback decisions are derived from tenant-scoped ledger state, not process-local guesses.
- Current runtime routing behavior remains TypeScript-only for all modes while no `MafAgentRuntimeClient` or `agent-service` exists.

## What Went Well

- The team preserved the strangler boundary. Epic 2 added contracts, ledgers, barrier checks, and retry semantics without creating early Python service/client code.
- OpenAPI 3.1 worked as a neutral contract source. The same valid and invalid fixtures now exercise both TypeScript and Python validation paths.
- Review loops materially improved the implementation. Important invariants were tightened after review: strict date-time parity, action lifecycle consistency, ledger monotonicity, tenant-scoped action rows, closed-barrier fallback behavior, idempotency-gated retryability, and stable failure reasons.
- Verification discipline improved compared with Epic 1. Story records consistently document targeted tests, package builds, full `pnpm test`, and `git diff --check`.

## Challenges

- Contract evolution repeatedly surfaced semantic invariants that OpenAPI schema alone could not express, such as retry total equality and action lifecycle consistency.
- Review findings clustered around the same risk class: stale identifiers, mismatched attempts, contradictory state, and unsafe defaults at runtime boundaries.
- The current `ProcessMessageRequest` shim still keeps `requestId`, `eventId`, and `runtimeAttempt` optional for compatibility. That is acceptable for this slice, but it is a known tightening point before real HTTP runtime traffic.
- Database integration tests could not fully execute locally because `DATABASE_URL` was not set; the command ran and skipped the integration cases.

## Key Lessons

- Treat contract validation as schema plus semantics. Some safety rules need explicit validator code and invalid fixtures in both TypeScript and Python.
- Runtime identifiers are part of the safety model. `traceId`, `runtimeAttempt`, request ID, event ID, tenant ID, and message ID must be compared, not rewritten.
- Fallback must be conservative by construction. Unknown or closed durable barrier state cannot become fallback-open through default values.
- Stable diagnostic reason codes are not documentation polish; they are the durable operational interface for retry, fallback, and audit behavior.
- Do not advance to candidate runtime execution until baseline and shadow diagnostics exist. Epic 2 created the safety substrate, not a candidate MAF runtime.

## Technical Debt And Deferred Work

- `ProcessMessageRequest` compatibility shim still allows missing `requestId`, `eventId`, and `runtimeAttempt`. This should become a strict runtime-boundary type or an explicit precondition before a real `MafAgentRuntimeClient` sends HTTP traffic.
- Full structured shadow diagnostics persistence is intentionally deferred to Epic 3 Story 3.2.
- Real Python service, FastAPI routes, MAF workflow, durable MAF sessions, internal service auth, and deployable service metadata remain deferred to later epics.
- Database integration verification remains environment-dependent until a local `DATABASE_URL` is provided.
