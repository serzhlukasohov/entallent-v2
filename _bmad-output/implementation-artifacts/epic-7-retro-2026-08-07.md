## Completed Scope

- Story 7.1: Added `agent-framework-core` inside `agent-service`, introduced a Microsoft Agent Framework workflow runner, preserved deterministic candidate results, and kept `modelCalls: 0`.
- Story 7.2: Added a confined `ConversationModelClient` abstraction, a Microsoft Agent Framework `Agent` adapter, an OpenAI-compatible async chat client, opt-in model settings, and safe model-provider error handling.
- Story 7.2 review fixes: enforced workflow-level MAF Agent timeout, normalized whitespace-only model config, rejected direct user-text echo, rejected OpenAI-compatible `content_filter` finish reasons, widened Python write scope guardrails, restored unprefixed `OTEL_SERVICE_NAME` compatibility, and clarified docs.

## What Went Well

- The migration objective was corrected explicitly: Python was introduced so Microsoft Agent Framework could be adopted, and Epic 7 now proves that adoption in code.
- The default path remains deterministic and credential-free, so local development and CI are not blocked by provider secrets.
- Review pressure found model-provider hazards before live testing: hung Agent execution, whitespace-only config, unsafe output echo, provider content filtering, and incomplete scope guardrails.
- Framework types stayed confined to `agent-service`; shared TypeScript contracts remained framework-neutral.
- The implementation preserved TypeScript side-effect ownership while allowing real MAF-generated candidate replies for inspection.

## Challenges

- The earlier epics built necessary safety and routing infrastructure before the real framework path existed, which made the migration feel slower than the original intent.
- The rollout plan has tension between fast-track testing and the pre-existing canary ceremony. With no real users, local and staging smoke tests should move faster, but user-facing routing still needs an explicit story.
- Provider package compatibility is still a moving target. `agent-framework-openai` was not hard-pinned because the local package reality did not support doing that safely.
- The worktree remains noisy from accumulated migration stories, so review and verification must stay scoped.
- Live model behavior has not yet been smoke-tested with real credentials in this environment.

## Key Lessons

- The framework adoption milestone must be named directly. Infrastructure-only progress is valid, but it does not satisfy the core goal until Microsoft Agent Framework is actually in the execution path.
- Fast-track does not mean removing safety boundaries. It means testing sooner while keeping Python proposal-only and TypeScript-owned side effects intact.
- Live model provider code needs stricter edge handling than deterministic workflow code: timeouts, empty output, filtered output, direct echo, and configuration normalization are all first-class behavior.
- Documentation must distinguish candidate execution, shadow diagnostics, canary routing, and ownership transfer. Treating them as one step would hide risk.
- The next useful confidence signal is a local live smoke test with real provider env vars and redacted evidence, not another scaffold layer.

## Technical Debt And Deferred Work
