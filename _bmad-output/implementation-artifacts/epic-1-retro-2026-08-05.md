# Epic 1 Retrospective: Runtime Boundary And Operator Control

Date: 2026-08-05
Project: enTalentNew
Epic Status: complete
Retrospective Status: complete

## Epic Review

Epic 1 established the MAF migration control plane without changing user-facing conversation execution. The completed slice keeps the TypeScript runtime as the production behavior, routes inbound jobs through `AgentRuntimePort`, evaluates runtime mode per job, supports kill-switch and denylist controls, and logs runtime decisions with traceable, privacy-safe fields.

## Completed Scope

- Story 1.1: Preserved TypeScript runtime behind `AgentRuntimePort`.
- Story 1.2: Added `AgentRuntimeRouter` with TypeScript default and fail-closed warning behavior.
- Story 1.3: Added MAF runtime control flags, precedence, denylist handling, and admin-visible runtime keys.
- Story 1.4: Added structured runtime decision logging with decision sources and sanitized fallback reason codes.

## Evidence

- `ConversationProcessor` remains dependent on `AGENT_RUNTIME_PORT`, preserving AD-1.
- `AgentRuntimeRouter` owns runtime selection and all current modes still delegate to `TypeScriptAgentRuntime`, preserving AD-5 and AD-13.
- Runtime flag precedence is explicit: global kill switch, tenant/user denylist, shadow, canary, TypeScript default.
- Runtime decision logs include `traceId`, `tenantId`, `userId`, `mode`, `decisionSource`, and optional sanitized `fallbackReason`.
- Workspace regression validation passed after Story 1.4 review fixes.

## What Went Well

- The migration started with a behavior-preserving boundary instead of a broad rewrite.
- The runtime router stayed framework-neutral in `packages/application`; Nest and repository wiring remained at the worker composition boundary.
- Review feedback improved the foundation materially: logger failures cannot block fallback, denylist evaluation is explicit, and fallback logging no longer exposes raw error text.
- Focused test commands became reliable for this slice, especially `pnpm --filter @entalent/application test -- agent-runtime`.

## Challenges

- Story 1.1 was implemented before a dedicated story artifact existed, so the execution record is less complete than Stories 1.2-1.4.
- Several review findings repeated the same underlying pattern: compatibility and privacy need to be designed into the first draft, not patched only during review.
- `application build` cleans `packages/application/dist`; running dependent worker typecheck in parallel can produce transient declaration-resolution failures.
- Runtime decision models currently live near the router/resolver. Epic 2 should decide the canonical contract/source before adding more cross-runtime shape definitions.

## Key Lessons

- Keep the strangler boundary narrow: route through the port, delegate to TypeScript, and add observability before adding new execution paths.
- Treat logs as an API. Runtime logs need stable reason codes and explicit allowed fields; raw exception messages are not acceptable in rollout/audit logs.
- Preserve public API compatibility when adding richer decision data. Add a new decision-returning method when existing callers expect a simpler mode result.
- Validate injected strategy output even in application-layer tests. A malformed evaluator must fail closed before it can corrupt audit fields.
- Sequence verification when package builds clean shared `dist` folders before downstream typechecks.
