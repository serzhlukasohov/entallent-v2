Communication Architecture Audit

The intended architecture is sound, but implementation ownership has split across two conversation brains, four commit paths, two context snapshots, and a runtime contract broader than the accepted mentor-companion model.

Verdict: changes required. Do not add another framework, graph, queue, or store. Converge the existing code into one TypeScript prepare-render-commit turn and narrow MAF to a renderer.

Order of work

P0 — trustworthy boundaries

  1. Runtime endpoint auth.
  2. Tenant-scoped user insights.
  3. Generated OpenAPI package artifact and default CI parity gate.
  4. PostgreSQL Slack idempotency and deterministic BullMQ job IDs.
  5. Truthful ledger phases tied to real commits.

P1 — one vertical conversation slice

  1. One TypeScript context snapshot with goals and persisted dialogue state.
  2. One classifier/risk pass and one DialoguePolicy.
  3. MAF reduced to reply rendering and diagnostics.
  4. One validate-and-commit function for direct OpenAI and MAF candidates.
  5. Silent extractor-created follow-ups disabled until consent is modeled.

P2 — remove scaffolding

  1. One proactive initiative executor and daily budget.
  2. Remove the conversation queue's special check-in branch.
  3. After the rollback window, delete shadow/canary-only machinery and the legacy whole-turn runtime path.
  4. Resolve admin-versus-manager privacy semantics.

Ponytail result

Delete dead risk/follow-up-planning queues, the deprecated ReplyBrief path, Python's duplicate classifier/memory/follow-up workflow, nominal unused ports, and one of the two context snapshots. Shrink four commit paths into one and use generated schema validation.

Net: approximately −1,500 to −2,500 production lines, zero new dependencies. Another roughly 1,000 lines become removable after the MAF rollback window closes.
