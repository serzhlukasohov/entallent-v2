Keep V1 group records and already issued report snapshots as historical data; do not reinterpret them as V2 question insights or rescore them implicitly. No archived MAF or `agent-service` work.

## Cross-cutting invariants

1. A final analytical row is unique by tenant, person, cycle, survey definition, and question version. It has no source message IDs, raw text, prompt payload, or reversible link to a message.
2. The private processing boundary alone owns temporary and confirmed semantic text. Assessment occurs before de-identification; a final analytical row requires privacy-accepted text and either a valid integer score or an explicit `insufficient_evidence` outcome with no score.
3. A durable final commit and private-content purge are one recovery-safe operation. Decline, reset, supersession, and cutoff have their own purge paths.
4. Missing, declined, or unresolved meanings have no score. One or two confirmed questions never create an employee-level Index score.
5. A cycle fixes one company Scoring Policy version. Cross-version trends have no official direction until rescored; same-version non-zero deltas are directional.
6. The reporting boundary sees only de-identified projections and restricted identity keys for eligibility. Customer roles and shared administrative credentials cannot read private conversation or working analytical content.
7. Cutoff waits for a durably persisted in-period employee reply to an unresolved delivered Bundle until its conversation job succeeds or is deliberately skipped. A content-free, message-scoped receipt then releases the cutoff sweep. A worker failure creates no receipt, so retry retains the restricted Bundle. The conversation worker attempts cleanup immediately after a receipt; the scheduled cutoff remains the recovery path. Rapid-message coalescing never drops an eligible Bundle reply.
8. Slack admission persists a content-free conversation job record in the same PostgreSQL transaction as the inbound message. The API and cutoff recovery use the same message-derived BullMQ job ID. After cutoff, recovery may replay an admission never marked queued when its durable source-event timestamp falls before the window end, even if API receipt or queue execution happened later. If the original scoped job is retained in BullMQ as completed but its receipt is absent, recovery queues only the content-free receipt retry. Failed or evicted jobs require separate side-effect reconciliation. The receipt remains the cleanup authority.

## Migration and rollout checks

- Add only forward SQL. Existing `survey_group_states` proof constraints remain for legacy V1 rows; V2 uses separate question proof and lifecycle constraints.
- Bind a V2 cycle to a complete approved rubric set before activating question scoring. Do not silently fall back to the V1 `70/30` scorer.
- Inspect all read/write paths for `survey_evidence`, `survey_assessments`, `survey_group_states`, `messages`, report snapshots, and internal admin endpoints before cutover.
- Treat existing report snapshots as immutable historical outputs. New V2 analytical inputs must not be mixed with them or with an Engagement scale that has no approved conversion.
- Run a local migrated PostgreSQL acceptance suite before any deployment decision. Production migrations and activation require their own target review and deployment evidence.
