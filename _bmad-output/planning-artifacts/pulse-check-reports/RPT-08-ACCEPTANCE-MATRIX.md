## Execution registration and accounting

P01–P04 assertions belong to `packages/database/src/__tests__/pulse-report-connected-acceptance.integration.test.ts`; P05 to `pulse-report-restart-acceptance.integration.test.ts`; P06 to `pulse-report-migration-acceptance.integration.test.ts` in that same directory. P07 runner/readiness assertions belong to the proposed colocated script tests and consume actual integration artifacts. Existing lower-level tests listed above remain the exhaustive arithmetic/privacy/calendar/presentation regressions; explicitly select those whose exact assertions are used in an executed row. Do not replace a connected phase with a direct repository seed, or count unselected historical tests as fresh evidence.

P06 is a required cross-cutting compatibility dimension for source/rights/receipt/history/language rows, not a new product AC. G03 public intake and G04 production wiring remain mandatory blocked prerequisites across relevant rows. No current public-ingress test or production bootstrap test exists to cite as acceptance. G05/G06/G07/G09/G10/G11 are distinct resource, semantic, client, production, authorization and execution gates; see design for exact evidence requirements.

The runner emits one case-level record per selected assertion and one33-ID trace map; each product row holds separate local/semantic/public/client evidence references. Duplicate/missing IDs, unexpected skips, old source hashes, missing artifact hashes, a failed case hidden by successful aggregate or an empty test selection fails accounting. No requirement is silently waived. Local RPT-08 completion means the required local oracles and conservative readiness accounting pass; full reporting/pilot acceptance remains blocked until every applicable external dimension is independently accepted.
