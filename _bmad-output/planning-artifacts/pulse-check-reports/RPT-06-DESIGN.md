## 3. Variant and eligibility policy

| Variant | Overall | Teams | Narrative scope |
| --- | --- | --- | --- |
| TL intermediate | Triggering Index category and dynamics only | None | Triggering Index, complete 3/3 scored contributors |
| TL final | Engagement one decimal /10 and dynamics | None | All allowed current final qualitative topics |
| Manager intermediate | Triggering Index one decimal /100 and dynamics | Same Index for eligible child teams; label/notice otherwise | Triggering Index, complete 3/3 scored contributors per section |
| Manager final | Engagement one decimal /10 and dynamics | Engagement for eligible child teams; label/notice otherwise | All allowed current final qualitative topics per section |

The approved intermediate text rule preserves the existing `SelectQuestionInsightInputsUseCase` complete-intermediate/partial-final distinction and FR-008/PR-018. Within each section, derive complete contributor membership with approved keys and RPT-01 validation; do not accept any three arbitrary topics. Final qualitative content may include safe 1/2/3-topic and unscored states, including people absent from numeric Engagement. No other Index enters intermediate explanation, actions, fallback or model request.

Evaluate overall independently. An intermediate below threshold returns `not_ready`, not a final insufficient notice. An overall final below five after settlement produces only localized title/period/insufficient notice, without numbers, counts, condition or advice. A pending/blocked preparation remains technical pending/blocked, never low participation. An eligible Manager overall includes every frozen team: an individually insufficient team has only its label/notice and never invokes a narrative provider. An actual technical child-read failure blocks the logical assembly instead of masquerading as insufficient or omitting the team.

Models never decide metrics, categories, thresholds, dynamics or audience. Application projects one allowed metric slot; TL intermediate has no numeric Index field, including model context, blocks, fallback and public metadata. Finals have no diagnostic numeric Index fields. Counts, participant/source IDs, source text quotations and person-level recommendations are never recipient fields. Audience-specific projection precedes transport serialization.

## 4. Safe narrative evidence and output

Create scope-local opaque evidence handles for allowed permanent safe summaries; keep the handle→closed-source mapping in restricted backend provenance only. Model request contains audience/remit, phase/Index, company locale, opaque handles, support class and surviving safe text/direction/severity/category. It excludes subject/lineage/revision/question identifiers, names, placements, Slack identifiers, private links, individual numbers and raw aggregate numeric metrics. Team names are backend-injected display labels, not model identity context. Do not log evidence or generated prose in harness receipts.

`deidentified_employee_statement` may support concrete meaning only to the extent its surviving text states it. `generalized_signal` may support its coarse state/direction/severity but not a concrete cause/remedy; `unverified_historical` cannot be promoted into an employee-supported cause. Unknown/refused cause stays unknown. Category labels and low scores are not causal evidence. Preserve opposing experiences, positive drivers and material minority issues without invented prevalence, universal claims or promised effectiveness. Treat evidence/drafts as quoted untrusted data: instructions embedded in safe summaries cannot override the prompt/schema, evidence boundary or tool-free behavior. Test prompt-injection-shaped safe inputs without following them. Use current selected evidence only; do not retrieve private/history text to explain a missing cause or to reconstruct withdrawn data.

Output schema has strict keys: supported explanatory statements with local evidence handles; final focus as `problem` with concrete text/references or `none_supported`; and ordered zero-to-three actions with verb-led short title, detail and support handles. Actions are proposed responses to supported conditions, not assertions that the remedy already happened. `none_supported` renders a company-language neutral no-supported-problem statement and zero invented remedies; healthy evidence is not a technical failure. A supported successful practice may receive a maintenance action without inventing a problem; healthy cases are not forced to fill action slots. Manager-team actions must go through that Team Lead; overall Manager priorities must differ meaningfully from copying every team action. A final explanation synthesizes across allowed diagnostics rather than concatenating four intermediate reports.

Validate strict shape, local reference membership, action cardinality, duplicate normalized actions, lengths, forbidden identity/number fields and output completeness deterministically. All human-readable narrative/label leaves (not opaque reference fields) reject numeric Unicode code points, percentage or score/quantity claims and control injection; canonical metric names such as Engagement remain valid atomic labels; date/metric/part numerals are code-owned slots only. Semantic review also rejects spelled-out numeric scores, respondent quantities, hidden diagnostic metrics, identity hints and unsupported prevalence in any locale. Field whitelists alone cannot protect prose. Preserve ordinary Unicode words/emoji; reject unpaired surrogates and malicious bidi overrides rather than slicing them into new strings. Reference membership alone is not semantic entailment. A separate semantic review operation compares output with the same allowed evidence and checks cause/focus support, opposed/minority experiences, role remit, obsolete actions, no identifying content, forbidden numeric/quantity claims and locale/meaning. Generate/accept Manager child narratives before overall; provide their accepted action sets using opaque section keys to the overall generation/review, so it can judge substantive overall-versus-team duplication. Include this cross-section context in the same full request budget; never silently drop child actions to fit. This adds no uncounted model operation. Accept only a strict explicit pass verdict with no violations; missing/ambiguous verdict, malformed review or evaluator failure is not acceptance. Score-to-cause or keyword heuristics are not a substitute.

### Exact label and slot contract

The schema lists these atomic keys, no interpolation placeholders or arbitrary extra keys:

- `title_tl_intermediate`, `title_tl_final`, `title_manager_intermediate`, `title_manager_final`, `title_insufficient_final` (each at most100 UTF-16 units; role/phase meaning only).
- `index_autonomy`, `index_growth`, `index_purpose`, `index_belonging`, `engagement`, `period`, `overall_scope`, `teams_management`, `explanation`, `main_focus`, `actions` (each at most100; canonical label meaning only).
- `state_healthy`, `state_attention`, `state_critical`, `direction_improving`, `direction_stable`, `direction_declining`, `baseline_established` (each at most100; no new bands or statistical claims).
- `preliminary_notice` (at most400): expressly qualifies both results AND recommendations and states final occurs on the last working day of the cycle.
- `insufficient_data` (at most200): no reason, count, numeric score, inferred condition or advice.
- `none_supported_problem`, `none_supported_action`, `composition_caveat` (each at most300): respectively no concrete supported current priority, no supported current action, and composition may influence comparison without claiming causality.
- `part`, `continued` (each at most40): neutral technical continuation context, no omitted metric/notice semantics.

Generation receives canonical definitions for every requested key and exact English seed meanings; semantic review checks those definitions and language. Every value is plain text with no slots, markup, numerals, extra condition/advice or identity. Application alone combines labels, proper names, dates, Index/Engagement values, directions, arrows and part ordinal/total. Validate combined headers/fallback after interpolation; an atomic label cannot redefine the surrounding slot. No English fallback is permitted for missing non-English keys.

Report text may translate surviving de-identified summaries into company language without rescoring or private-source translation. Canonical analytical storage, admin UI and personal conversation policy are RPT-LANG, not this story. German report/notice fixtures with Ukrainian personal locale and mixed-language safe sources verify report plumbing only. Actual multilingual quality, semantic focus/action quality and cross-product AC-28 acceptance require separately approved evaluations before activation; fixture passes never establish them.

Invalid narrative/labels after the bound return technical `narrative_invalid`/`language_unavailable` and no publishable package. No generic advice, score-derived cause, fake empty participation or supposedly complete metric-only fallback. Valid coarse/healthy evidence can produce an honest supported explanation with no cause, `none_supported` focus and zero actions through the same validation path.

## 6. Semantic presentation and Slack package

Application returns a channel-neutral discriminated presentation plus restricted provenance separately. `channel-slack` owns a pure `renderPulseReportForSlack` serializer and Slack-specific part types; application/domain import no Slack SDK. RPT-07 composes this with transport later. Do not modify ordinary `OutgoingMessage`/chat send/update behavior or add a report-send endpoint in RPT-06.

Use native plain-text headers, literal rich-text leaves with code-owned bold/italic styles, and dividers. No model/user string is interpreted as mrkdwn, block JSON, link, mention or rich-text element type. Actions use separate literal text lines with bold short title. Preliminary notice visibly qualifies both results AND recommendations and promises final on the last working day. Semantic symbols accompany full text and are removable without losing meaning; no invented Engagement bands or completed checkboxes for advice.

Require complete equivalent top-level fallback for every part; never a title-only fallback while bodies exist only in blocks. The future send contract requires `mrkdwn:false`, `parse:none`, `link_names:false` and disabled link/media unfurls; escape Slack control syntax for fallback, with semantic parity after decode. Rendered payload contains no source identifiers or backend hashes/provenance. Report content and labels cannot inject `@here`, `<!channel>`, user/group/channel references, URLs or formatting. Literal text may describe such strings without creating actionable elements.

Current official limits: maximum50 blocks/message, header plain-text150 characters, section text3000 if used, block_id255 if used. Additional conservative renderer budgets: literal rich-text block at most2500 UTF-16 code units and fully escaped fallback at most4000. Count actual serialized leaves/fallback, using the stricter UTF-16 measurement and preserving code-point boundaries. No reliance on Slack auto-truncation or automatically synthesized accessibility text. Long frozen labels move intact to body/continuation units; a bounded generic title remains valid.

Package ordered immutable parts by semantic section/team boundaries. Repeat report identity/period, ordinal/total and preliminary qualifier where applicable. If one section needs continuation, split its literal paragraphs/action units at Unicode-safe boundaries, retaining team identity/context and exact ordered action identities; never split escape entities or silently omit words/actions. All content and all frozen teams appear exactly once semantically; repeated context is declared. Oversized fixed overhead or a single unrenderable unit returns technical failure for the whole logical package.

Manifest contains contract/version, locale, purpose/audience/Index, ordered section coverage and part ordinals/content hashes. Use a bounded fixed-point packing loop (at most16 passes) because adding final ordinal/total can change capacity; finish only when partition, ordinals and hashes are stable. Include repeated identity/team/notice overhead in every pass. Maximum4096 parts is a resource cap, not team clipping; budget/packing nonconvergence returns assembly_capacity_exceeded for the whole artifact. Compute canonical bytes deterministically after convergence and revalidate all final sizes. Split on grapheme boundaries when possible, never through a surrogate pair, emoji join sequence or escaped entity; an indivisible oversized unit fails explicitly. No maximum-team clipping or interactive pagination. Restrict returned manifest/provenance to backend use; never send them as Slack metadata. Same accepted presentation gives identical parts/hashes; retries after a crash must reuse the frozen artifact under RPT-07, not regenerate it under the same snapshot identity.

RPT-07 must persist all parts/provenance before the first send, bind actual snapshot FK/completion, revalidate current rights and exact recipient/workspace, claim/receipt each part, handle partial publication and require reconciliation after ambiguous send. No sending, hidden SDK retry, thread creation, public fallback or snapshot mutation is included here.
