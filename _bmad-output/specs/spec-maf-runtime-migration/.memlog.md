- (direction) Use express mode from the provided migration plan and brownfield repository context; create the SPEC in English per project BMAD config.
- (decision) Migration target is hybrid first: TypeScript keeps Slack ingestion, BullMQ scheduling, authorization, tenant isolation, Postgres ownership, and action execution while Python/MAF owns agent orchestration behind a stable runtime boundary.
- (capability) CAP-1: The worker can choose between the existing TypeScript runtime and a MAF runtime client through a framework-neutral AgentRuntimePort with feature-flag and kill-switch rollback.
- (capability) CAP-2: The Python agent service can process one inbound conversation turn via FastAPI and Microsoft Agent Framework workflow execution, returning structured reply, risk, memory proposals, proposed actions, trace ID, and runtime version.
- (capability) CAP-3: The migration can run shadow comparisons where TypeScript answers users and MAF runs asynchronously for result, risk, memory, action, latency, and cost comparison.
- (capability) CAP-4: Regression and release gates can compare MAF behavior against existing conversation-sim scenarios and an expanded sensitive-scenario baseline before any canary rollout.
- (constraint) Do not rewrite Slack ingestion, BullMQ queues, tenant isolation, authorization, admin API, analytics, or the Postgres schema in the first MAF migration slice.
- (constraint) No aggregate may have concurrent TypeScript and Python writers; Python returns proposals or commands until ownership is explicitly transferred per aggregate.
- (constraint) Fallback from MAF to TypeScript is allowed only before side effects; every request and proposed action needs idempotency keys.
- (constraint) Production MAF hosting must not rely on process-local session or in-memory history; session state and conversation history remain separately durable.
- (constraint) MAF framework types must stay inside the Python agent runtime and must not leak into TypeScript domain contracts or shared domain modules.
- (assumption) Assume the first vertical slice covers inbound user message processing with context load, intent/risk analysis, memory extraction proposals, response generation, follow-up proposals, and structured result return.
- (question) Which transport contract should the MAF client expose first: JSON-only HTTP or HTTP plus SSE streaming for partial responses and trace events?
- (question) Should the first MAF service use the prerelease agent-framework-hosting helpers or plain FastAPI routes over core agent-framework only?
