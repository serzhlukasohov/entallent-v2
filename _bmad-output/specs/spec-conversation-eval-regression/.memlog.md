- (event) Gaps found: no case format tied to Confluence IDs; results are per scenario not per criterion; no framework statuses or layer scoring; no baseline diff between runs; judge never calibrated against human labels; no injectable clock (orchestrator has 7 direct Date uses, quiet-hours util reads new Date()); no pulse-cycle fixtures for uncovered topics / index progress; LANGWATCH_API_KEY optional streaming only; Langfuse only as env vars, not wired.
- (decision) Keep LangWatch Scenario as the live-simulation driver (already adopted, vendor-neutral locally); LangWatch cloud stays optional via API key; do not add Langfuse for this work.
- (decision) Architecture: one case-as-data format mirroring the Confluence case structure, executed by three executors: L0 deterministic (scripted model, injected clock, scheduler use cases), L1 orchestrator-level live simulation (existing harness + fixtures), L2 application-level through /dev endpoints against local API+worker+Postgres+Redis. Slack stays manual (thin smoke, P-06 production observation).
- (decision) Per-criterion status model and verdict follow Framework v2.1.1 sections 5 and 6 exactly; S criteria are a hard gate; meaning-based statuses are advisory until judge agreement with human labels passes a threshold.
- (decision) Regression detection is a diff of per-criterion results against the last stored baseline (git sha, models, level), with N-run thresholds per criterion instead of per scenario.
- (decision) Judge evaluates the reply named by evaluatedAt with the transcript up to that reply, one structured PASS/FAIL/reason per criterion; the judge model is pinned per suite version.
- (constraint) TypeScript-only; retired MAF/agent-service untouched; rule checks stay inside the test framework, no lexical heuristics migrate into product code (ADR-013 D2).
- (constraint) L0 and L1 need no Postgres/Redis; the conversation-sim test script stays offline; L2 targets only the local docker stack through development-only /dev endpoints, never Railway production.
- (constraint) Exact suite texts are sent verbatim via scripted steps; the user simulator is not used for suite cases. Existing ScenarioRunReport and gate summary consumers keep working (additive or versioned schema).
